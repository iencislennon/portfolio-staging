## Context

Analysts and policy advisers facing a drought, an energy price spike or a supply disruption have to merge crop, transport, power and market signals quickly. CrisisNet was built for a lablab.ai hackathon as a virtual crisis team: you describe the situation in plain language and get a structured report with a recommended policy.

## My contribution

All 16 commits in the repository are authored by me. Whether others contributed outside the repository, and how the hackathon credits the team, still has to be confirmed against the lablab.ai submission page, so I am not describing team roles here.

## Constraints

Hackathon time, LLM API dependence (no key means no demo), and no real ground truth for crisis outcomes. Reports are demonstrations of the pipeline, not advice.

## Architecture

Four specialist agents publish typed payloads (Pydantic schemas) to a shared coordinator. The coordinator checks them against each other and passes a summary to a fifth agent, the Regulator, which returns a policy recommendation, a confidence score and an escalation flag. Every publication is written to an audit trail.

## Decisions

- **Typed payloads between agents.** Strict schemas make each agent's output checkable and testable without calling an LLM.
- **Explicit conflict rules.** Four rules compare outputs directly, for example a large crop deficit paired with a low logistics risk score, or price cuts recommended while stock is critically low.
- **Human in the loop.** The Regulator can set an escalation flag with a reason instead of forcing a recommendation.
- **Reports as artifacts.** Output is available as Markdown, JSON or PDF; generated reports are not tracked in Git, with one labelled sample kept in the docs.

## Evaluation

The coordinator logic is covered by eight unit tests: each of the four conflict rules, the exact thresholds (30% deficit, 0.3 risk, 14 days of stock), readiness once four agents have published, and the audit trail. These test the coordination rules, not the quality of LLM-generated analysis, which has not been measured.

## What failed

The original repository had a hardcoded `localhost` backend address in the frontend, generated reports committed to Git, a mismatch between the README title and the project name, and no hosted demo that I could verify. I removed the hardcoded address (the frontend now reads `VITE_API_URL`), untracked the generated reports and removed any unverified demo link.

## Impact

None claimed. This is a working pipeline and a tested coordination layer, not a deployed product with users.

## Next iteration

A deterministic offline mode, request timeouts and cost limits, rate limiting, and an end-to-end smoke test.

## Reproducibility

`pip install -r requirements.txt`, set `FEATHERLESS_API_KEY` in `.env`, run `python -m uvicorn backend.main:app`, and check `/health`. The coordinator tests need only `pydantic`, `loguru` and `pytest`.
